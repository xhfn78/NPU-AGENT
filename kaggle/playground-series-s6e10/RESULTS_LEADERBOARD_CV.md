## 이번에 바꾼 점

기존 단일 80:20 분할 대신 seed=20261028의 공통 층화 5-fold를 사용합니다.
각 폴드는 학습 559,708행과 검증 139,927행으로 구성됩니다.
LightGBM, XGBoost, CatBoost를 각각 5번 학습해 총 15개 모델을 만듭니다.
각 학습 행에는 그 행을 학습하지 않은 모델의 OOF 예측이 하나씩 할당됩니다.

각 모델은 기존에 유효했던 서비스/여행 조건 타깃 인코딩, 원본 보조 예측/통계,
거리·좌석 등급별 서비스 평균을 사용합니다. CatBoost에도 거리별 서비스 특징을 추가했습니다.
타깃 인코딩은 외부 검증 폴드의 정답을 제외하고, 학습 부분 안에서 내부 5-fold로 계산합니다.
범주 매핑과 서비스 평균도 해당 학습 부분에서만 계산합니다.
공개 원본 데이터의 보조 특징은 대회 데이터의 정답과 별개로 만든 기존 특징을 재사용합니다.

동일한 OOF 행에서 세 모델의 확률/logit 조합을 비교해 가중치를 선택합니다.
테스트 확률은 각 모델의 5개 폴드 예측을 평균한 다음 선택한 가중치로 결합합니다.
새 test 정답이나 다른 참가자의 예측 파일은 사용하지 않습니다.

## 점수 해석

OOF 정답은 early stopping과 최종 가중치 선택에 사용합니다.
따라서 OOF AUC는 모델 선택용이며 독립 테스트 점수가 아닙니다.
또한 기존 단일 분할 점수와 새 전체 OOF 점수의 차이를 그대로 개선 폭으로 계산하지 않습니다.
같은 OOF에서 단독 모델과 결합 모델을 비교하고, 새 제출 파일의 실제 Kaggle 평가로 확인합니다.

`selection.json`의 `target.leaderboard_score_for_this_file`과 `target.goal_reached`는
Kaggle 평가 전까지 `null`입니다. OOF AUC가 0.963을 넘더라도 리더보드 목표 달성으로 처리하지 않습니다.

## 실행

```powershell
cd C:\study\kaggle\playground-series-s6e10

```

완료 폴드는 같은 데이터·설정·코드 해시에서 재사용합니다.
`train`은 폴드 학습만, `export`는 완료한 폴드의 OOF 조합 선택과 제출 파일 출력을 수행합니다.
설정이나 코드가 달라지면 새 출력 폴더를 사용해야 합니다.
기존 ML 패키지와 공개 원본 보조 특징이 필요하며 추가 패키지 설치는 없습니다.
Kaggle에는 자동 제출하지 않습니다.

실행 환경은 Python 3.11.0, scikit-learn 1.9.1, XGBoost 3.2.0,
CatBoost 1.2.10, LightGBM 4.7.0입니다. 상세 버전은 `runtime_versions.json`에 있습니다.

## 산출물

- `submission_cv.csv`: Kaggle 제출용 `id,satisfaction` CSV.
- `selection.json`: 각 모델/조합의 전체 OOF 및 폴드별 점수, 실제 선택, 리더보드 목표 상태.
- `verification.json`: 행 수·ID·확률 범위·CSV 저장 오차·파일 SHA-256.
- `fold_ids.npy`: 모든 학습 행의 폴드 번호.
- `*_oof.npy`, `*_test_mean.npy`: 모델별 OOF와 평균 테스트 예측.
- `fold_0`~`fold_4`: native 모델, 검증/test 예측, 인코더/범주 매핑, 트리 수와 재로딩 검사.
- `manifest.json`: 입력 원본·보조 특징·코드 SHA-256, 전체 모델 설정과 분할 설정.

이전 모델과 제출 파일은 각 기존 폴더에 보존했습니다.
